# Agents — Поэтическая Полка (Stih)

Справочник по проекту для AI-агентов.

## Обзор

Клиентское SPA для хранения и чтения поэзии. Без бэкенда, без сборщика, без фреймворков. Данные живут в `localStorage`. Язык интерфейса — русский.

## Архитектура

Классическая MVC, реализованная через ES6 классы:

| Класс | Файл | Роль |
|---|---|---|
| `PoemApp` | `assets/app.js` | Контроллер. Инициализация, привязка событий, координация Store и UI |
| `PoemStore` | `assets/store.js` | Модель. CRUD авторов/произведений, localStorage, импорт/экспорт, закладки, поиск дубликатов |
| `PoemUI` | `assets/ui.js` | Представление. Рендеринг списков, карточек, модальных окон, навигация |
| `TimelineBar` | `assets/timebar.js` | Компонент временной шкалы (годы, точки, выпадающие меню) |
| `DuplicateDetector` | `assets/DuplicateDetector.js` | Поиск дубликатов авторов и произведений |

Глобальные утилиты без привязки к классам — в `assets/utilities.js`:
- `escapeHtml()` — экранирование HTML (используется повсеместно)
- `compressImage()` / `imageUrlToBase64()` — сжатие фото авторов
- `normalizeUnicode()` / `cleanPastedText()` — очистка вставленного текста
- `convertEngToRus()` — конвертация английской раскладки в русскую для поиска
- `cropImageToCircle()` / `convertToGrayscale()` — обработка фото авторов для EPUB
- `sortAZ()` / `sortPosts()` — сортировка авторов и произведений

Хелперы поиска `isAuthorMatch()` / `isPostMatch()` объявлены в `store.js` вне класса — используются и в Store, и в UI.

Склонение слов (`getAgeWord()`) и разбор ссылок YouTube — методы `PoemUI`, не утилиты.

`stripTags()` — метод `PoemStore`, а не глобальная утилита: чистит HTML
произведения для EPUB-экспорта.

Константы имён и значений — в `assets/storage-keys.js`:
- `STORAGE_KEYS` — все ключи `localStorage`, которые пишет приложение
- `THEME`, `FONT_SIZE`, `COLUMNS`, `SORT_AUTHORS` — допустимые значения настроек
- `STORAGE_DEFAULTS` — значения по умолчанию

Файл подключается в `index.html` **первым**, раньше jQuery: остальной код
обращается к `STORAGE_KEYS.*` при загрузке. Строками ключи в коде не писать —
опечатка тихо ломает настройку без единой ошибки в консоли.

## Модель данных

Структура в localStorage (`stih_app_data`):

```
{ data: { authors: [Author], meta: { version, lastModified, authorsCount, postsCount } } }
```

**Author:**
```
{
  id: "author_<timestamp>",
  lastName, firstName, surName,
  birthYear, deathYear,           // number | null
  photo,                          // base64 строка | ""
  posts: [Post]
}
```

**Post:**
```
{
  id: "post_<timestamp>",
  title,
  content,                        // plain text (если не HTML)
  contentHtml,                    // HTML разметка (если включён HTML-режим)
  year,                           // number | null
  note,                           // заметка/контекст
  links: [{ title, url }]         // внешние ссылки
}
```

**Поля `translation` у `Post` нет.** Раньше оно было описано здесь, но код его
нигде не читает и не пишет, а в реальной библиотеке (194 произведения) оно
отсутствует у всех. Перевод хранится не отдельным полем, а **внутри `content`:
оригинал и перевод идут подряд, через строку**, а `detectTranslationPattern()`
в `ui.js` распознаёт их по алфавиту и решает, показывать ли две колонки.
Поэтому в описании модели это поле фигурировать не должно.

## Зависимости

- `jquery` 4.x, `bootstrap` 5.3.x — через `node_modules/`, подключены в `index.html`
- `JSZip`, `FileSaver.js` — тоже через `node_modules/`, не с CDN. Приложение обязано запускаться без сети, поэтому **ни один ресурс не подключается по внешнему URL**
- Шрифты: Merriweather, Playfair Display, Plus Jakarta Sans — локальные woff2 в `assets/fonts/`
- Исключение, и то необязательное: превью видео YouTube грузится по наведению (`loadYouTubeThumbnails()` в `ui.js`). Без сети контейнер превью удаляется через `img.onerror`, ссылка работает как обычно

## Стили

- `assets/styles.css` — основные стили (~1230 строк). CSS-переменные для цветов и размеров. Классы `vintage-app`, `font-small/normal/large`, `cols-1/2/3/4`
- `assets/theme-dark.css` — тёмная тема (~380 строк). Активируется через `data-theme="dark"` на `<body>`

## Порядок подключения скриптов

```
storage-keys.js → jquery → bootstrap → DuplicateDetector.js → timebar.js → utilities.js → store.js → ui.js → app.js → JSZip → FileSaver
```

Порядок важен: каждый следующий файл зависит от предыдущих. Первые три
(`storage-keys.js`, `jquery`, `bootstrap`) нужны до всего остального —
константы настроек читаются при загрузке, а jQuery требуется всем остальным
модулям на этапе определения классов и вызовов.

## Точка входа

```js
$(document).ready(() => {
    window.app = new PoemApp();
    window.app.init();
});
```

`window.app` — глобальная ссылка на приложение, используется в обработчиках событий.

## Ключевые паттерны

- **Нет сборщика** — все файлы загружаются как обычные `<script>`. При добавлении нового файла его нужно подключить в `index.html` в правильном порядке
- **jQuery для DOM** — используется `$()` для выборки, событий, анимаций. Не смешивать с React/Vue
- **Bootstrap модалки** — `bootstrap.Modal` для форм авторов, произведений, выбора авторов для EPUB, поиска дубликатов
- **localStorage как БД** — все данные в одном ключе `STORAGE_KEYS.DATA` (`stih_app_data`). Настройки лежат в отдельных ключах, объявленных в `storage-keys.js`: `THEME`, `FONT_SIZE`, `COLUMNS`, `AUTHOR_SORT`, `POST_BOOKMARKS`, `LAST_VIEWED`, `SELECTED_AUTHOR`, `SELECTED_POST`, `SIDEBAR_WIDTH`, `EPUB_AUTHORS`, `TITLE_INDEX`, `SUBTITLE_INDEX`
- **Счётчик изменений** — ключ `STORAGE_KEYS.UNSAVED_COUNT`, отображается бейджем на кнопке "Данные". Сбрасывается при экспорте
- **Распознавание переводов** — `detectTranslationPattern()` в `ui.js` решает, показывать ли произведение в две колонки «оригинал | перевод» (кнопка `⇆`). Пороги — константы `TRANSLATION_*` рядом с функцией. Гейты `MIN_PAIRS` и `MIN_COVERAGE` обнуляют confidence ДО вычисления, поэтому неверные значения там дают тихое «не перевод», а не исключение
- **XSS** — любые пользовательские данные, попадающие в `innerHTML`, обязательно проходят через `escapeHtml()`. Правило проверяется тестами
- **Случайные заголовки** — массивы `PoemApp.poeticTitles` и `PoemApp.poeticSubtitles` ротируются каждые 30 секунд в шапке
- **Выбор авторов для EPUB** — модальное окно `epubAuthorsModal` позволяет пользователю выбрать авторов для экспорта. Выбор сохраняется в `localStorage` под ключом `STORAGE_KEYS.EPUB_AUTHORS`
- **Поиск дубликатов** — `DuplicateDetector` ищет дубликаты по ФИО авторов и названиям произведений. Результаты отображаются в модальном окне `duplicatesModal` с вкладками

## MCP Server и интеграция с AI

Для работы внешних AI-агентов с библиотекой в корне проекта находится скрипт `server.php`, реализующий протокол Model Context Protocol (MCP) по стандарту JSON-RPC (STDIN/STDOUT).

### Основные функции MCP-сервера:
1. **get_library_stats** — получение статистики и пути к последнему бэкапу библиотеки.
2. **list_authors** — вывод всех авторов и количества их произведений.
3. **search_poems** — полнотекстовый поиск произведений по названию или содержимому.
4. **get_poem** — получение полного текста произведения по его ID.
5. **add_author** — создание нового автора.
6. **add_poem** — добавление произведения существующему автору.
7. **update_poem** — редактирование произведения.

### Бэкапы и мета-данные:
* Данные MCP-сервер загружает из самого свежего JSON-файла резервной копии вида `stih_backup_YYYY-MM-DD.json`.
* Новые или измененные данные сохраняются в файл с текущей датой в имени, обновляя объект `meta` (версия, дата изменения, количество авторов и произведений).
* Для импорта/экспорта в веб-интерфейсе поддерживается обратная совместимость (как со старой плоской структурой с массивом авторов, так и с новой структурой, содержащей объект `meta`).

### Логирование:
* Все запросы, вызовы инструментов, а также операции чтения и записи бэкап-файлов записываются в лог-файл `mcp_server.log` в корне проекта. Файл в `.gitignore`.
* **Содержимое аргументов в лог не пишется** — только имена полей и их размеры (`{title: 42 симв., content: 1200 симв.}`), см. `describeArgs()` в `server.php`. Лог не гимгинируется, а раньше туда попадал полный текст произведений и переводов. Если понадобится содержимое — включать осознанно и отдельным флагом.
* Логирование помогает отслеживать действия агентов и понимать, какие операции выполнялись с библиотекой.

### Подключение и конфигурация MCP:
* Для подключения сервера AI-агенту (например, в Claude Desktop) используется файл конфигурации `mcp.example.json` в качестве шаблона.
* В секцию конфигурации `mcpServers` добавляется описание сервера:
  ```json
  "poetic-shelf": {
    "command": "php",
    "args": [
      "/абсолютный/путь/к/проекту/server.php",
      "/абсолютный/путь/к/проекту"
    ]
  }
  ```
* **Первый аргумент** — это абсолютный путь к PHP-файлу `server.php` в вашей системе.
* **Второй аргумент** — это абсолютный путь к директории проекта. Он передается в `server.php` как путь для чтения/записи файлов резервного копирования (`stih_backup_*.json`) и лог-файла (`mcp_server.log`).

## При внесении изменений

- Проект открывается прямо через `index.html` или `npx serve .`
- Логика без DOM покрыта тестами: `npm test` (`node --test`, встроенный раннер, зависимостей нет). Есть `tests/utilities_test.js`, `tests/translation_test.js`, `tests/duplicate_detector_test.js`
- Тесты читают **реальные файлы** из `assets/` и выполняют их в `node:vm` — так проверяется код, который работает в браузере, а не его копия. Новый тест добавляется в `tests/` с суффиксом `_test.js`
- Тесты, зависящие от DOM (`renderDuplicateResults`, рендер карточек), в Node не запускаются — для них проверять вручную в браузере
- Комментарии в коде на русском языке
- JSDoc используется для документации функций
- `npm install` для загрузки `node_modules/` (jQuery, Bootstrap, JSZip, FileSaver)
- **Никаких внешних URL в `<script>`, `<link>` и `@font-face`** — приложение работает без сети. Новую библиотеку ставить через `npm`, а не через CDN. Проверить: `grep -rEo 'https?://[^"]+' index.html assets/*.css` не должен давать ничего, кроме `xmlns`-namespace'ов (w3.org, daisy.org, idpf.org) и ссылок, которые открывает сам пользователь по клику
- При добавлении новых модальных окон — использовать существующий паттерн Bootstrap 5 модалок
- При добавлении новых настроек — добавлять ключ в `STORAGE_KEYS` (`assets/storage-keys.js`), а значение, если оно перечисляемое, — в `THEME` / `FONT_SIZE` / `COLUMNS` / `SORT_AUTHORS`
- При изменении модели данных — обновлять раздел «Модель данных» и обратную совместимость в `importJson()`
- Коммиты, теги и пуш делает пользователь — агент не коммитит без прямой просьбы
